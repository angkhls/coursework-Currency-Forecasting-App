> Чек-лист предназначен для выполнения проверок из задания 3.2. На момент создания все пункты имеют статус «Не выполнено»: отметьте их только после реальной проверки. Фактический результат, статус, дата, окружение и ссылка на скриншот/видео заносятся в `test-execution.md`. Этот чек-лист не заменяет тест-кейсы задания 3.3.

## Условия и правила выполнения

- Для автоматических проверок запускайте backend и тесты в изолированном Python virtualenv.
- Внешние источники в тестах подменяйте моками/HTTP-заглушками; не полагайтесь на доступность реальных API.
- Для UI-пунктов запускайте backend и frontend, фиксируйте браузер и размер экрана.
- Негативная проверка должна проверять ожидаемую валидацию/ошибку/fallback, а не только факт, что запрос завершился.
- «Негативная проверка» означает проверку неправильного ввода, пустых данных, отказа зависимости или недоступного сценария, в зависимости от требования.
- Если требование нельзя проверить в текущем окружении, оставьте незачёркнутым и запишите `Blocked` с причиной в отчёте выполнения.
