# Нагрузочное тестирование — задания 5.1, 5.2 и 5.3

Сценарий нагрузки: tests/load/locustfile.py
Исполнитель прогона: tests/load/run_load_test.py
График результатов: docs/test-evidence/load-test-chart.png

## 1. План нагрузочного тестирования (5.1)
- Цели (NFR-01, NFR-05): подтвердить отклик стандартных запросов <= 3000 мс, определить пик RPS и точку деградации при росте нагрузки, проверить восстановление после снятия нагрузки.
- Профиль нагрузки: смешанный поток 4:3:2:1 (dashboard, convert, chart, forecast); пауза между действиями 20 мс в ускоренном прогоне (0.5-1.5 с в Locust).
- Виды тестов: базовый (1 пользователь), нагрузочный (10, 25 пользователей), стресс-тест (50, 100, 150 пользователей) и восстановление (1 пользователь).
- Критерии успешности: Error rate <= 1% (факт 0%), p95 <= 3000 мс.

## 3. Анализ деградации и узких мест
- Точка начала деградации: 50 одновременных пользователей (пик 103.0 RPS; далее при 100-150 пользователях RPS падает до 92.2-93.0, а p95 растёт до 2215.3 мс).
- Узкие места: синхронная подгонка SARIMAX внутри async-обработчика FastAPI без кэширования и выноса в пул потоков, а также один воркер Uvicorn с последовательным доступом к SQLite.
